# Документация пользователя

[English](user-guide.en.md) · [README](../README.ru.md) · [Документация разработчика](developer-guide.ru.md)

### Требования

- Linux или другая Unix-подобная среда с Bash.
- Установленный Apache Kafka.
- Исполняемые утилиты:
  - `/opt/kafka/bin/kafka-topics.sh`;
  - `/opt/kafka/bin/kafka-acls.sh`.
- Kafka должна быть доступна по адресу `localhost:9092`.
- Файл клиентской конфигурации: `/opt/kafka/config/client_jenkins.conf`.
- Учётные данные из конфигурации должны позволять просматривать и создавать топики, а также просматривать и изменять ACL.
- Утилита `grep`.

### Установка

```bash
git clone https://github.com/Eksterulo/rekaf.git
cd rekaf
chmod +x rekaf.sh
```

### Синтаксис

```text
./rekaf.sh --topic <topic> [--producer <producer>] [--consumer <consumer> --group <group>]
```

| Параметр | Обязательность | Назначение |
| --- | --- | --- |
| `--topic <topic>` | всегда | Имя Kafka-топика |
| `--producer <producer>` | хотя бы producer или consumer | Имя principal продюсера без префикса `User:` |
| `--consumer <consumer>` | хотя бы producer или consumer | Имя principal консьюмера без префикса `User:` |
| `--group <group>` | с `--consumer` | Consumer group |
| `-h`, `--help` | нет | Показать справку |

`--group` нельзя использовать без `--consumer`.

### Примеры

Только продюсер:

```bash
./rekaf.sh --topic orders --producer orders-producer
```

Только консьюмер:

```bash
./rekaf.sh \
  --topic orders \
  --consumer orders-consumer \
  --group orders-group
```

Продюсер и консьюмер:

```bash
./rekaf.sh \
  --topic orders \
  --producer orders-producer \
  --consumer orders-consumer \
  --group orders-group
```

### Результат и повторный запуск

Скрипт выводит каждую проверку и выполненное изменение. Если топик или нужное ACL уже существуют, они повторно не создаются. Ошибки аргументов и предварительных проверок приводят к завершению с ненулевым кодом. Неудачная операция создания топика или добавления ACL также прерывает выполнение. Ошибка проверки существования ресурса может быть воспринята как его отсутствие и привести к попытке создания.

## Настройка окружения

В начале `rekaf.sh` заданы следующие значения:

```bash
KAFKA_BIN="/opt/kafka/bin"
BOOTSTRAP_SERVER="localhost:9092"
CONFIG="/opt/kafka/config/client_jenkins.conf"
```

Для другого окружения измените эти значения в скрипте. Аргументов или переменных окружения для их переопределения сейчас нет. Имя файла `client_jenkins.conf` — текущий путь к клиентской конфигурации; скрипт запускается обычной командой из терминала.

## Ограничения

- Пути к Kafka, bootstrap server и конфигурации жёстко заданы в скрипте.
- Проверка ACL основана на текстовом выводе `kafka-acls.sh` и `grep`; изменение формата вывода может потребовать корректировки.
- Проверка ищет principal и operation как подстроки, но отдельно не валидирует тип разрешения и host. Совпадение не гарантирует наличие подходящего разрешающего ACL.
- Ошибки команд просмотра ресурсов могут быть восприняты как отсутствие топика или ACL; сообщения об ошибках просмотра ACL подавляются.
- Скрипт только добавляет права и не удаляет лишние ACL.
- Топик создаётся без явных `--partitions` и `--replication-factor`, с настройками брокера по умолчанию.

## Безопасность

Скрипт изменяет состояние Kafka. Перед запуском в production проверьте адрес кластера, клиентскую конфигурацию, имена principal, топик и consumer group. Сначала проверьте поведение на тестовом кластере.

Не сохраняйте секреты Kafka и клиентскую конфигурацию в репозитории. Храните конфигурацию отдельно и ограничьте доступ к ней.
