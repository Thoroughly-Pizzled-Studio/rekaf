# rekaf

`rekaf.sh` — Bash-скрипт для идемпотентного создания Apache Kafka-топика и выдачи минимально необходимых ACL продюсеру и/или консьюмеру.

## Что делает скрипт

1. Проверяет наличие указанного топика.
2. Создаёт топик, если его ещё нет.
3. Для консьюмера при необходимости добавляет:
   - `READ` для топика;
   - `READ` для consumer group.
4. Для продюсера при необходимости добавляет `WRITE` для топика.

Право `CREATE` клиентам намеренно не выдаётся: топик создаётся самим скриптом с административными учётными данными.

## Документация пользователя

### Требования

- Linux или другая Unix-подобная среда с Bash.
- Установленный Apache Kafka.
- Исполняемые утилиты:
  - `/opt/kafka/bin/kafka-topics.sh`;
  - `/opt/kafka/bin/kafka-acls.sh`.
- Kafka должна быть доступна по адресу `localhost:9092`.
- Файл клиентской конфигурации: `/opt/kafka/config/client_jenkins.conf`.
- Учётные данные из конфигурации должны позволять просматривать и создавать топики, а также просматривать и изменять ACL.
- Утилита `grep`.

### Установка

```bash
git clone https://github.com/Eksterulo/rekaf.git
cd rekaf
chmod +x rekaf.sh
```

### Синтаксис

```text
./rekaf.sh --topic <topic> [--producer <producer>] [--consumer <consumer> --group <group>]
```

| Параметр | Обязательность | Назначение |
| --- | --- | --- |
| `--topic <topic>` | всегда | Имя Kafka-топика |
| `--producer <producer>` | хотя бы producer или consumer | Имя principal продюсера без префикса `User:` |
| `--consumer <consumer>` | хотя бы producer или consumer | Имя principal консьюмера без префикса `User:` |
| `--group <group>` | с `--consumer` | Consumer group |
| `-h`, `--help` | нет | Показать справку |

`--group` нельзя использовать без `--consumer`.

### Примеры

Только продюсер:

```bash
./rekaf.sh --topic orders --producer orders-producer
```

Только консьюмер:

```bash
./rekaf.sh \
  --topic orders \
  --consumer orders-consumer \
  --group orders-group
```

Продюсер и консьюмер:

```bash
./rekaf.sh \
  --topic orders \
  --producer orders-producer \
  --consumer orders-consumer \
  --group orders-group
```

### Результат и повторный запуск

Скрипт выводит каждую проверку и выполненное изменение. Если топик или нужное ACL уже существуют, они повторно не создаются. При ошибке выполнение немедленно прекращается с ненулевым кодом возврата.

### Использование в Jenkins

Пример шага Pipeline:

```groovy
sh '''
  ./rekaf.sh \
    --topic orders \
    --producer orders-producer \
    --consumer orders-consumer \
    --group orders-group
'''
```

Не сохраняйте секреты Kafka в репозитории. Файл `client_jenkins.conf` должен создаваться на агенте Jenkins из Credentials или другого защищённого хранилища.

## Документация разработчика

### Структура

Репозиторий намеренно минимален:

```text
.
├── rekaf.sh
├── README.md
└── .gitignore
```

### Устройство скрипта

- `set -euo pipefail` включает строгую обработку ошибок, неинициализированных переменных и ошибок в конвейерах.
- Разбор аргументов выполняется циклом `while` и `case`.
- До обращения к Kafka проверяются комбинации параметров, исполняемые файлы Kafka и клиентская конфигурация.
- Общие параметры Kafka хранятся в массиве `COMMON_OPTIONS`.
- `topic_acl_exists` и `group_acl_exists` проверяют наличие ACL.
- Все изменяющие операции выполняются только после соответствующей проверки.

### Настройка окружения

В начале `rekaf.sh` заданы три константы:

```bash
KAFKA_BIN="/opt/kafka/bin"
BOOTSTRAP_SERVER="localhost:9092"
CONFIG="/opt/kafka/config/client_jenkins.conf"
```

Для другого окружения измените эти значения или доработайте скрипт, чтобы принимать их через аргументы либо переменные окружения.

Топик создаётся без явных `--partitions` и `--replication-factor`, поэтому применяются настройки брокера по умолчанию.

### Проверки перед изменениями

Рекомендуемый минимальный набор:

```bash
bash -n rekaf.sh
shellcheck rekaf.sh
```

Интеграционную проверку проводите на тестовом Kafka-кластере:

1. Запустите скрипт для нового топика.
2. Убедитесь, что топик и ACL созданы.
3. Запустите ту же команду повторно.
4. Убедитесь, что повторный запуск не создаёт дубликатов.
5. Проверьте producer-only, consumer-only и совместный сценарии.
6. Проверьте ошибки для пропущенных и несовместимых аргументов.

### Правила разработки

- Сохраняйте совместимость с Bash; скрипт использует массивы и `[[ ... ]]`, поэтому POSIX `sh` не поддерживается.
- Заключайте подстановки переменных в кавычки.
- Для новых конвейеров учитывайте `pipefail`.
- Не добавляйте секреты, клиентские конфигурации или credentials в репозиторий.
- Изменения ACL проверяйте на отдельном Kafka-кластере перед использованием в production.

### Известные ограничения

- Пути к Kafka, bootstrap server и конфигурации жёстко заданы.
- Проверка ACL основана на текстовом выводе `kafka-acls.sh` и `grep`; изменение формата вывода Kafka может потребовать корректировки.
- Проверка ищет principal и operation, но отдельно не валидирует тип разрешения и host.
- Скрипт только добавляет права и не удаляет лишние ACL.
- Параметры создания топика берутся из настроек Kafka по умолчанию.

## Безопасность

Скрипт изменяет состояние Kafka. Перед запуском в production проверьте адрес кластера, клиентскую конфигурацию, имена principal, топик и consumer group.
